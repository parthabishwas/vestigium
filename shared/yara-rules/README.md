# shared/yara-rules

The YARA rule store shared by the Linux and Windows collectors. Both scan
with `active-rules.yar`, which is built here from the sources below.

| Path | Versioned | Purpose |
|---|---|---|
| `sources.conf` | yes | Rule repositories (`<name> <git-url> [<ref>]`), in precedence order |
| `custom/` | yes | Your own rules; always built first |
| `exclusions.conf` | yes | `file:<glob>` drops files; `rule:<name>` makes a rule private (silent) |
| `rules.lock` | yes | Commits, yara version and bundle SHA256 of the last build; written by the builder |
| `signature-base/`, `rules/`, … | no | Source checkouts (DRL 1.1, GPL-2.0), fetched by setup |
| `active-rules.yar`, `active-rules.compiled` | no | The built bundle |
| `rule-build-report.csv`, `RuleBuildReport.csv`, `rule-fp-report.txt` | no | Build and false-positive reports |

```bash
sudo ./vestigium.sh setup --rules-only      # latest upstream -> rebuild -> rewrite rules.lock
sudo ./vestigium.sh setup --rules-locked    # rebuild exactly what rules.lock records
./vestigium.sh setup --verify               # sources, lock status, bundle age
```

```powershell
.\vestigium.ps1 setup            # Windows: latest -> rebuild -> rules.lock
.\vestigium.ps1 setup -Locked    # Windows: locked rebuild
```

Everything not versioned is regenerated by those commands and must never be
committed: the upstream licences do not allow this project to redistribute
the rules. The full lifecycle, file formats, tuning and CI loop are in
[docs/YARA-RULES.md](../../docs/YARA-RULES.md).
